HTTP Method

POST Requests

Three ways to POST data to your server: URL-encoded form fields, a JSON body, and a direct binary file upload.

application/x-www-form-urlencoded

Form POST

The default HTML form encoding. Fields are serialised as key=value&key2=value2 and sent as the request body. Your server must set CONTENT_TYPE and CONTENT_LENGTH before calling the CGI.

POST /cgi-bin/form.py HTTP/1.1 Content-Type: application/x-www-form-urlencoded Content-Length: — name=John+Doe&email=john%4042.fr&school=42+Paris&message=Hello+WebServ%21
RESPONSE —
application/json

JSON POST

Sends a raw JSON body. Your server must forward it to the CGI via stdin with CONTENT_TYPE=application/json and the correct CONTENT_LENGTH.

RESPONSE —
Direct file upload — application/octet-stream

POST direct file upload

The file is sent as-is in the request body with Content-Type: application/octet-stream. No multipart boundary, no encoding — just raw bytes. Your server writes whatever it receives in the body straight to the destination path.
